# Native NB Social Psychology textbook

This extends the genuine NB server and nbclient forks. It does not call the legacy SQLite social-reading API. Server base4f1d722 and client basef26b5f7 preserve their upstream ancestry. The frozen Social Psychology collection is published at `/books/social_psychology/`, with entry chapter `/books/social_psychology/13:_Competition_and_Cooperation_in_Our_Social_Worlds/13.01:_Conflict_Cooperation_Morality_and_Fairness/`.

The publisher retains the main reading DOM and attribution, rewrites collection navigation, removes only the legacy annotation script/metadata/style, and adds the native NB client and book-specific controls. Textbook layout, existing Reader and Listen assets remain separate from native discussion controls. Inherited unavailable-image placeholders remain inherited content limitations. No previous legacy feature is claimed ported.

Keyboard users choose an actual paragraph in the labeled passage chooser and activate Discuss selected passage. This creates a browser selection and invokes the native mouseup annotation seam. Pointer users select text normally. Both use NB's own editor, course/source model, API, HTML ranges, annotations and replies. The client change scopes the native page margin to preserve book layout. Mobile presents NB in a lower panel. No new legacy editor or backend is introduced.

## Build and incremental installation

1. Publish the read-only snapshot to a fresh stage with `python3 scripts/textbook-publish.py SNAPSHOT NEW_STAGE`. Supply a frozen same-origin `_assets` closure; no arbitrary remote HTML is fetched by the app. Keep asset provenance and source page hashes in the external packet. Validate every local referenced asset and navigation link. Input snapshots are never modified.
2. Commit/review both forks. Run `deploy/nb-demo/build-release.sh https://nb.libretexts.dev CLIENT_REPO OUTPUT CLIENT_SHA NEW_STAGE`. The fifth argument includes verified content; omitted, the sample-only baseline still builds. It refuses changed page digests or symlinked content. Each release includes the native client, textbook and an empty uploads directory required by native multer startup.
3. Chief alone checks the exact installed source/preimages, takes `backup.sh`, installs the pinned archive and activates with the existing reviewed scripts. Preserve the existing sample, accounts, database, environment, Caddy and legacy sites. The server automatically serves an included textbook; no new proxy block is needed. This code was locally staged, not host-executed by Annotation Dev.
4. Chief runs `NB_TEXTBOOK_MANIFEST=/opt/nb-demo/current/textbook/textbook-manifest.json NB_DEMO_OPERATOR_DIR=/var/lib/nb-demo-operator NB_DEMO_ORIGIN=https://nb.libretexts.dev NB_DEMO_PORT=3475 /opt/nb-demo-runtime/bin/node /opt/nb-demo/current/scripts/textbook-register.cjs` in a protected operator context. Registration signs in the existing synthetic instructor and adds native source/file records to the existing demo course; it never creates users, posts or replies. Interrupted registration reuses existing source URLs; a matching completed receipt returns reused. Changed manifests/origins are refused rather than silently reanchoring old records. No secrets belong in the packet.
5. Verify public reading/navigation and authenticated source access, then return the exact HTTPS deep link. Source rollback uses the existing previous-release mechanism, retaining all database rows and new book source records. Data restore is a separate explicit operation. Never delete book annotations to roll back code.

Live updates, uploads and follow/unfollow remain disabled. No production, grant, accessibility or all-browser qualification follows from these local tests. VoiceOver remains owner-skipped. Local synthetic creation/reply/restart evidence must remain distinct from Chief's later live checks.
